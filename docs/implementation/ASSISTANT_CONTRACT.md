# Assistant and floating helper contract

Contracted 2026-10-04. This slice is a user-operated route assistant, not autonomous app control or screen guidance. No screen is captured, no accessibility content is read, and no message/call/payment is dispatched.

- `AssistantActivity` is non-exported and owns the general-assistant microphone. The explicit Home **Ask Asha** gesture creates a one-use, 15-second in-process authorization through `voiceIntent(context)`. It is consumed on the first foreground entry and removed from the Intent; arbitrary extras, replay, restored state and cancellation cannot authorize listening. Exact local voice commands from this Home gesture may open allowlisted owned screens. They never send, call or pay. Plain assistant Speak and helper voice remain editable drafts. Microphone permission and a speech-provider disclosure still precede recognition; unknown/cloud requests require review and submission. Opening Home itself never starts listening. Background, Stop, cancellation and destruction invalidate callbacks and disconnect optional inference. The QR screen separately retains explicit foreground amount dictation with local parsing only. The phone speech provider may process audio remotely; no offline-recognition promise is made.
- Deterministic Hindi/English routes open Home, family selection, Apps, alarms, family help and the owned WhatsApp-family workflow. Recipient selection and final communication stay in `CommunicationActivity` and the receiving app. Ambiguous requests remain editable. A QR/payment classification does not execute a transaction or silently interpret an amount.
- Optional `/intent` classification requires a configured HTTPS endpoint, explicit `ai_cloud_consent` bound to that endpoint, and a new explicit request. Only the submitted text is sent. No screenshots, photos, contact directory or passive speech are included. Speech-provider processing is a separate disclosure; offline speech is not promised.
- Backend replies accept only `call`, `media`, `qr`, `help`, `home`, `unsupported`. HTTP redirects are refused; input, response size and connection/read times are bounded. Unknown keys/types/actions fail closed. Cancellation/background prevents a late route even if already-transmitted bytes cannot be recalled. Tokens and transcripts are not logged.
- Floating helper starts from explicit user enablement. A collapsed movable control expands to the configured assistant, Family and Home plus collapse/stop. Assistant identity defaults to Asha, is normalized to a single line and bounded to 24 Unicode code points; names are independent of the Maa package/app name. Drag position and intended enablement persist; actual attachment is reported separately. Loss of overlay permission, app stop or close removes the window. No claim of guaranteed restart or continuous overlay confinement is made.
- Service notification provides a stop action and foreground assistant entry. A desired-on preference does not prove the service is currently visible. Root must use the exposed live-state check for health. Boot restart is outside this slice; Android may stop the process.

Integration: declare `.AssistantActivity` non-exported; call `voiceIntent` only from the explicit Home Ask gesture. `AssistantIdentity.askLabel(context)` supplies its localized configurable label. Existing overlay/foreground-service permissions and speech-service package query remain relevant. No new broad package query or screen-observation permission is required.

Use `HelpOverlayService.start(context)` for generation-stamped explicit enablement and `stop(context)` for disablement. Stop synchronously clears requested/attached state and publishes updates. `isActive(context)` checks current-generation attachment and overlay permission; `isRequested(context)` reports desired state. Stale service callbacks and old button commands cannot reverse a newer stop. A later permission grant requires an explicit start unless Android independently restarts an authorized service request.

Verification: compile and focused instrumentation under the root build coordinator; manual microphone grant/deny/revoke, unavailable recognition, cancel/background during inference, changed endpoint, denied overlay, drag/clamp/rotation, service close and process death. Any unexecuted test remains unverified. Tests must not send messages, place calls or make payments.
